# Day 27 — Capstone Design & Architecture: Missing Pieces & Enhancement Opportunities

_Analysis date: 2026-08-04_

1. **`ProjectTask.Result` has no default value under nullable reference types** — Every other string property on `ProjectTask` (`Id`, `Description`, `AssignedTo`) is initialized to `string.Empty`, but `Result` is declared as `public string Result { get; set; }` with no initializer. With `<Nullable>enable</Nullable>` set in the csproj, this should generate a CS8618 "non-nullable property must contain a non-null value" warning, and any code that reads `task.Result` before it's assigned (e.g., printing an incomplete task) will get a null reference silently treated as non-null. A future revision should give it `= string.Empty;` like its siblings for consistency and to eliminate the warning.

2. **No error handling around the LLM call in `GoalRefinerAgent`** — `ExecuteAsync` calls `_kernel.InvokePromptAsync` with no try/catch, no timeout, and no retry. Since this agent's entire contract is "mutate `state.RefinedGoal`," an unhandled exception here (network failure, rate limit, content filter rejection) crashes the whole console app with no useful message and leaves `RefinedGoal` at its default empty string. Given that later capstone days will chain several agents together, this is the first and easiest place to introduce a pattern for resilient agent execution before the chain gets longer.

3. **No validation that the refined goal is non-empty or well-formed** — `state.RefinedGoal = result.ToString().Trim();` accepts whatever the model returns, including a possible empty string, a refusal, or leftover instruction text if the model doesn't follow the prompt precisely. There's no check before printing the state or handing it off, so a bad refinement would silently propagate into Day 28's Planner with no warning at this layer.

4. **Shared state exists only in memory for a single run** — Unlike Day 25's `MemoryManager`, which persists state to disk so it survives a restart, `ProjectState` here is purely an in-process object that's discarded the moment the console app exits. For a capstone about managing a project (which in the real world spans more than one process lifetime), there's no serialization/checkpointing story yet — worth flagging as a natural enhancement once more agents are added and a single run takes longer.

5. **No cancellation support** — Neither `Main` nor `GoalRefinerAgent.ExecuteAsync` accepts or threads through a `CancellationToken`, so there's no way to interrupt a slow or hung model call. This matters more as the capstone grows additional agents in subsequent days, each adding more sequential await points with no way to abort the whole pipeline partway through.

6. **No unit tests for `ProjectState.IsFullyCompleted` or `GoalRefinerAgent`** — `IsFullyCompleted`'s logic (`Tasks.Any() && Tasks.All(t => t.IsCompleted)`) has a subtle edge case — an empty task list reports "not complete" rather than "trivially complete" — which is reasonable but untested and unexplained in code comments. Similarly, `GoalRefinerAgent` has no test double / fake `IChatCompletionService` to verify its prompt-construction or state-mutation logic without making a real network call.

7. **All core types are `internal`, foreclosing reuse or testing from another assembly** — `ProjectState`, `ProjectTask`, `IProjectAgent`, and `GoalRefinerAgent` are all declared `internal class`/`internal interface`. This is fine for a single console-app demo, but if a later revision wants to add a separate test project or split the plugin/agent library out from the console host (a natural refactor as the capstone grows), these will all need to become `public` or the test project will need `InternalsVisibleTo`.
