# Day 13 — Prompt Logic Plugins: Missing Pieces & Enhancement Opportunities

_Analysis date: 2026-08-04_

1. **No error handling around the prompt invocation** — `kernel.InvokePromptAsync(promptTemplate, arguments)` is unguarded; a network failure, template-rendering error (e.g., a missing variable), or API rejection will crash the program with an unhandled exception. Since this lesson's template calls two plugin functions during rendering, a rendering-time exception thrown from inside `GetPurchaseList` or `GetTierInstructions` would be just as fatal and just as invisible to the student — a try/catch around the invocation with a clear message would help isolate template/plugin errors from model/network errors.
2. **No null-argument guarding inside the plugin functions** — `GetPurchaseList` checks `user.RecentPurchases == null` but never checks whether `user` itself is null, and `GetTierInstructions` calls `tier.Equals(...)` with no null-check on `tier` at all — if the template ever invoked these functions with a missing or null argument (e.g., a typo in a `KernelArguments` key), the result would be an unhandled `NullReferenceException` deep inside a plugin call. Since the code comment explicitly frames this plugin as an example of "ordinary, testable C# methods," adding basic guard clauses (and ideally unit tests exercising the null cases) would reinforce that testability claim rather than just asserting it.
3. **The plugin functions are never actually unit tested** — The lesson's whole premise is that moving logic into a plugin class makes it "testable," but there is no test project or test method anywhere in this solution proving that out. A follow-up revision could add a companion xUnit/MSTest project with a few tests against `GetPurchaseList` and `GetTierInstructions` directly (no Kernel involved) to make the testability payoff concrete instead of just asserted in a comment.
4. **Only two tiers are handled, with a silent fallback** — `GetTierInstructions` treats anything not equal to `"Gold"` as the generic/default tier, silently. There's no explicit handling (or even a code comment) acknowledging tiers like "Silver" or "Platinum" that a real system might have, so the binary if/else reads more like a placeholder than a complete example of the "conditional logic" concept it's meant to showcase. Expanding to three or more tiers (or using an enum instead of a raw string) would better demonstrate genuinely non-trivial conditional logic.
5. **`Tier` is a raw string instead of an enum** — `UserProfile.Tier` and `GetTierInstructions(string tier)` both use plain strings for a value that is conceptually a small, fixed set of categories. This invites typos (e.g., "gold" vs "Gold" vs "GOLD", partially mitigated here by `OrdinalIgnoreCase`, but "Gol d" or an unrecognized tier name would silently fall into the generic branch with no warning). Introducing a `MembershipTier` enum would be a natural, low-risk improvement and a good teaching moment about type-safety in plugin parameters.
6. **Unused `using System.Text;` directive** — The file imports `System.Text` but never uses it (the purchase-list formatting uses `string.Join`, not `StringBuilder`); a documentation/code cleanup pass should either remove the unused directive or use it meaningfully, e.g., switching `GetPurchaseList` to build its output with a `StringBuilder` as a secondary demonstration of that API.
7. **No demonstration of what happens when a plugin function throws or a template variable is missing** — The lesson would benefit pedagogically from showing (even in a comment or a second run) what error surfaces when, say, `arguments` is missing the `"tier"` key that `{{UserHelperPlugin.GetTierInstructions $tier}}` needs — this is exactly the kind of failure mode students will hit once they start writing their own plugins, and the lesson currently only shows the success path.
8. **No cancellation token support** — `InvokePromptAsync` is called without a `CancellationToken`, consistent with every other lesson in this batch, so there's no way to cancel an in-flight request from within the app.
