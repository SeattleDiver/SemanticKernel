# Day 2 — The Summarizer: Missing Pieces & Enhancement Opportunities

_Analysis date: 2026-08-04_

1. **No error handling for file I/O or the model call** — `File.ReadAllTextAsync`, `File.WriteAllText`, and `InvokePromptAsync` all run with no try/catch. If `article.txt` were locked by another process, or the Gemini call failed (network error, bad key, rate limit), the program crashes with a raw stack trace. Since this lesson's whole premise is "feed a file into an LLM," a follow-up revision should show at least one guarded path (e.g., catching `IOException` around the read and a generic catch around the AI call) so students see file-based agents need to handle a file that isn't there.
2. **Hard-coded output path with no overwrite protection** — `CreateDummyArticle` always writes to `"article.txt"` relative to the current working directory and silently overwrites whatever is there via `File.WriteAllText`. There's no check for an existing real file, no configurable path, and no warning if a student's own `article.txt` gets clobbered. A future version could accept a path via `args` and fall back to the demo article only if no file is supplied.
3. **No validation of the summarization output** — The code trusts that the model actually returned exactly 3 bullet points as instructed; there's no parsing, counting, or retry if the model returns 2, 5, or a paragraph instead. This is a good opportunity to introduce students to the general problem of LLM instruction-following being probabilistic, not guaranteed, and to show a simple validation/retry pattern.
4. **Typo left in a student-facing prompt string** — The prompt template contains "ingore minor details" instead of "ignore." It doesn't break functionality, but since students are told to treat this code as the source of truth to learn from, a follow-up pass should fix it so it isn't copied forward into their own prompts.
5. **No execution settings / temperature control** — Unlike Day 3 and later lessons, this program never constructs a `GeminiPromptExecutionSettings` object, so summarization runs at whatever the provider's default temperature is. Since summarization benefits from a lower, more deterministic temperature, this lesson would be a natural place to introduce that concept a day earlier than Day 3 does, even if only briefly.
6. **No token/length guardrails on the input** — The demo article is short, but nothing in the code addresses what happens if a student points this at a much larger file that exceeds the model's context window. A short comment or guard (e.g., truncating or chunking very large inputs) would prepare students for real-world summarization tasks.
7. **Variable name typo (`aguments`)** — The `KernelArguments` variable is spelled `aguments` instead of `arguments`. Harmless to execution, but worth a cleanup pass since students often copy-paste this file verbatim as a starting point for their own prompt-template experiments.
